# cli.md — flag reference with examples

`greedyfind` takes one of two mode flags and a range. All
other flags are optional.

## Synopsis

```
greedyfind --pubkey <hex>  --from <int> --to <int> [options]
greedyfind --address <b58> --from <int> --to <int> [options]
```

## Required (one of)

### `--pubkey <hex>`

A SEC1 hex public key. Compressed (33 bytes) and uncompressed
(65 bytes) are both accepted.

```bash
greedyfind --pubkey 0279BE667EF9DCBBAC55A06295CE870B07029BFCDB2DCE28D959F2815B16F81798 \
           --from 0 --to 16
```

### `--address <base58>`

A P2PKH mainnet address (base58check). Testnet and P2SH are
not supported in v0.1.

```bash
greedyfind --address 1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH \
           --from 0 --to 16
```

## Required for both modes

### `--from <int>`

First scalar `j` in `[from, to)`. Decimal. Range is
`[0, 2^256)`.

### `--to <int>`

Last scalar `j` (exclusive). Decimal. Must be > `--from`.

## Optional

### `--cache-points`

Persist X-coordinates to a per-target cache file. The cache
uses the same byte layout as the `find` Rust crate, so a
cache generated by `find` can be loaded by `greedyfind` and
vice versa.

### `--batch-size <n>`

Number of points per batch normalisation. Default 32. Larger
batches amortise the per-batch field-inversion cost; smaller
batches reduce per-threadgroup memory pressure (the variant
table + bitmap + G-point state).

### `--variants <n>`

Number of variants: 256 or 512. Default 512. 256 reduces the
variant index from 16 KiB to 8 KiB, useful when threadgroup
memory is the bottleneck.

### `--anchor-interval <k>`

Anchors every `2^k` threadgroups. Default 16. Larger `k`
spreads the per-anchor precomputation over more threadgroups;
smaller `k` refreshes the anchor more often (cheaper per-step
EC add, more anchor work).

### `--gpu <idx|all>`

Use a specific GPU index, or all. Default all. On a 2-GPU
M-series box, `--gpu all` dispatches to both; the A44 load
balancer rebalances between them.

### `--resume`

Resume from the last checkpoint in `--output-dir`. The
checkpoint is a small JSON file with a SHA-256 integrity hash;
see `host/checkpoint.{h,m}` for the format.

### `--output-dir <dir>`

Output directory for the cache, checkpoints, and matches.
Default `./greedyfind-out`.

### `--log-dir <dir>`

Log directory for NDJSON telemetry and the human-readable
rolling log. Default `./greedyfind-out`.

## Examples

### Pubkey sweep over a tiny range (smoke test)

```bash
./build/greedyfind \
    --pubkey 0279BE667EF9DCBBAC55A06295CE870B07029BFCDB2DCE28D959F2815B16F81798 \
    --from 0 --to 16
```

Expected output: a `MATCH j=1` line.

### Address sweep with cache + resume

```bash
./build/greedyfind \
    --address 1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH \
    --from 1182668407300416828363925638565633982711 \
    --to   1182668407300416828363925638565633982739 \
    --cache-points --resume \
    --output-dir ./puzzle-71
```

### Two-GPU sweep

```bash
./build/greedyfind \
    --pubkey 02... \
    --from 0 --to 2^71 \
    --gpu all \
    --batch-size 64 \
    --anchor-interval 18
```

## Exit codes

| Code | Meaning |
|------|---------|
| 0    | Success (matches printed to stdout) |
| 64   | Argument parse failure |
| 70   | Internal error (Metal unavailable, kernel failed, etc.) |
